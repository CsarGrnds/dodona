# Dodona — agent instructions

Next.js 15 (App Router) + TypeScript. No CSS framework: styles live in `app/globals.css`.

- Server-only code: `lib/data/*`, `lib/agent.ts`, `lib/analyze.ts`, `app/api/*`. Never import these from client components.
- Client-only code: `lib/store.ts`, `lib/client.ts`, `components/*`, pages (all `"use client"`).
- `lib/indicators.ts`, `lib/signals.ts`, `lib/types.ts` are pure and shared.
- Rule factors must stay explainable: each one scores −2..+2 with a human-readable `detail`.
- The Claude agent must only reason from data passed to it; keep the "no invented numbers" rule in its system prompt.
- Yahoo returns some fields as percentages (fiveYearAvgDividendYield, debtToEquity); normalize to fractions in `lib/data/yahoo.ts`.
- Commit messages must start with `Claudia - ` (e.g. `Claudia - Add earnings-calendar trigger`).
- Secrets (API keys, GitHub tokens) live only in `.env` / `.env.local`, which are gitignored. Never hardcode or commit them; document new ones in `.env.example` with an empty value.
- The repo is public. README screenshots come only from the demo portfolio (`npm run demo:portfolio`, the `dodona-demo` launch config, `npm run screenshots`), never from a real account, a logged-in IBKR gateway or this machine's time zone.
- Keep `README.md` current in the same change: new pages, panels, API routes, scripts, skills, env vars and layout rows, and remove roadmap items that shipped.
- Before finishing a change: `npm test`, `npm run typecheck`, and `npm run dev` for a visual check with real market data (not mock mode).
- `.claude/skills/trader-*` are vendored day-trader skills (Python, stdlib only). They are not part of the Next.js app; don't import or call them from app code. Their working folder `trader/` is gitignored. Never place a broker order without the user's explicit yes for that exact order.
- The paper trade team (`/trade-desk` skill + `.claude/agents/trade-*.md` subagents) runs the trader skills in Claude Code, never from app code. They run with cwd `trader/paper/` (Dodona keeps it in step with the paper desk), never from the repo root, whose `trader/portfolio.json` is the real IBKR account. The team books only through `npm run desk -- book`, which requires trader-risk's PASS for that exact order; it never calls a broker or `/trader-broker`. Dodona only reads Claude Code transcripts (`lib/data/transcripts.ts`) to show the team's work, locally.
- `lib/data/ibkrOrders.ts` is the only code that can send an order (to IBKR, through the local gateway). Keep every gate: off unless `ibkr_orders` and `"broker": "ibkr"` are set, paper accounts (DU…) only while `"paper"` is true, trader-risk's PASS for that exact order in the last 15 minutes, never the same order twice, and the user's click in Dodona (with their typed confirmation, unless they turned on `one_click`, Settings → One-click approval, themselves). IBKR's questions are never auto-confirmed. Batches also refuse stocks the user already holds and trades whose IBKR fees exceed 25% of their risk. Today's stop tickets (`/api/ibkr/stop`) only raise or set one sell STOP on a holding: never down, never at or above the price, never under cost with "Never sell at a loss", never more shares than held, never the same change twice (a fractional stop, which IBKR's API can't modify, is replaced: the old one is canceled and confirmed gone, then a whole-share stop is sent; the user is told and texted if the holding is left without one), logged as `stop-changed` so trader-risk doesn't count them as trades. Claude never calls `POST /api/ibkr/orders` or `POST /api/ibkr/stop` with `place`, `answer` or `cancel`, never turns `paper` off or `one_click` on, and nothing scheduled (desk auto-run, `/loop`, the trade team) ever places a broker order. `/trade-desk live` only stages the morning batch (`npm run desk -- stage`); the user approves it in Dodona.
- Paper mode (`"paper"` in `trader/config.json`) is the one switch between practice and real money. The user flips it in Settings (`POST /api/settings/paper`, from a click on Dodona's page only; turning it off asks them to type REAL MONEY); Claude never calls it. While it's off, no practice runs (paper team cycles, the Desk's auto-run, `/api/desk/run`) because they'd spend tokens on fake trades, and the Desk shows the real IBKR account with no paper wording. While it's on, the Desk shows the practice ledger under a PAPER DESK watermark (`lib/data/practice.ts`).
- `lib/data/liveRun.ts` starts the trade team as a background `claude -p` session from the Desk's Run desk now button. Keep its allow list to the desk/gateway-status `npm` commands, the skill scripts and read-only tools; never add Edit/Write, web, curl or anything that reaches `/api/ibkr/orders`. A live run only stages and checks; the user places the batch.
- `trade-screener` builds the day's shortlist before the open (`npm run desk -- shortlist build`, rules in `lib/shortlist.ts`; Dodona starts `/trade-desk screen` at 9:15 AM New York when auto batches are on). It may only take names off (`shortlist drop`), never add one or loosen a rule; live runs' `desk pending` scans only today's shortlist.
- The trade team learns through `trader/playbook.md`, written only by `trade-coach` from `npm run desk -- review` (replays of logged candidates on real bars). Playbook lessons may only make the team pickier; they never change risk limits, sizes, the daily loss limit or `paper`. Subagent commands never use `$(...)`, `${...}`, backticks or `python3 -c`: background runs can't approve them (they read saved output with the Read tool).
- **Document every change to how the agents work, in the same change.** Anything that changes what an agent or the trade team does, may do, reads or is told (a new agent, mode, command, flag, gate, schedule, limit or rule) goes into this file (the rule and its guardrail), plus the skill or agent file that runs it (`.claude/skills/trade-desk/SKILL.md`, `.claude/agents/*.md`). Code comments and commit messages don't count: a future session only reliably reads this file and the skill it runs.
- The money and its limits: the user sets one amount ("Trading today" on the Desk, `budget` in `trader/config.json`). With `auto_from_budget` on, `max_loss_per_trade_usd`, `max_daily_loss_usd` and `max_order_usd` are worked out from it (`risk_pct`, `daily_loss_pct`, the cash buffer: `lib/budget.ts`) and written as dollars. Every team run is told the rules in force, read from `trader/config.json` when it starts (`rulesBrief`, printed by `desk session start` and added to the run's instructions); never reuse numbers from an earlier run or an example.
- The scout and the board: Dodona's watch (code, no Claude, `watch_every_min`, 9:46 AM-3 PM New York) scans today's shortlist, writes every stock's state to `trader/runs/board-<date>.json` (`lib/board.ts`) and wakes the team (`/trade-desk live SYM,…`) only for a ready range that's new today or for a re-check. Watch runs see only their stocks (`desk pending --only`, enforced by `DESK_ONLY`); one run at a time; it never wakes the team over a batch waiting for the user or without a logged-in gateway. Only code writes the board.
- Re-checks: the lead may mark a skip `--recheck volume|vwap|market` only when the skip rests solely on those (relative volume under 1.0, price under VWAP, SPY under its VWAP). The scout re-wakes the team for that stock when all of them clear, at most `MAX_RECHECKS` (2) times a day, `RECHECK_GAP_MIN` (20) minutes apart, and only after a new call was logged. Never add a reason a chart or the news decides (chart score, a single-wick range high, the Time Machine, earnings): those skips are final for the day. A re-check never loosens a rule; it only asks the same rules again.
- The coach reviews every trading day (catching up a missed one, two tries at most) and records a rule audit; a day is done once `trader/learning/reviews/<day>.json` has `reviewed_at`. Shortlists are kept per day in `trader/learning/shortlists/`.
- The strategist (`trade-strategist`, `/trade-desk research`, Saturdays from 10 AM New York while Dodona runs) runs `npm run research` (`scripts/research.ts`: every strategy in `lib/strategies.ts` on each morning's shortlist rebuilt without hindsight, IBKR's fees at the user's budget) and writes `trader/research/report.md`. It only reports: it never changes a rule, the playbook, `trader/config.json` or what the team trades, and only a strategy with verdict "edge" may be recommended, for practice first. The user turns a strategy on. Its research run may only run that command and write that report. The cache in `trader/research/cache/` holds today's data only.
